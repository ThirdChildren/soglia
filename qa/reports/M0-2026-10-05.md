## Failing items (blockers for "Gate PC superato")

### F1 - S0.1 verification 6: external URLs present in the production bundle

- Reproduce: `npm run build` then `grep -rIl "jsdelivr\|unpkg" src public iwsdk.config.json dist` (run from the project root).
- Expected: no output. Got: `dist/assets/index-PaaDS_P0.js`.
- Matches (from `grep -oE ".{80}(jsdelivr|unpkg).{80}" dist/assets/index-PaaDS_P0.js`):
  1. `const Jf=\`https://unpkg.com/three@0.${se}.0\`` - in the glTF loader init (`Nt.init`, next to `GLTFPayloadLimitError`), the default location of the Draco decoder.
  2. `const mZ="https://cdn.jsdelivr.net/npm/@webxr-input-profiles/assets@1.0/dist/profiles"` - default source of WebXR controller input profiles.
- Involved: `@iwsdk/core` 1.0.1 (bundled library code). The app's own sources (`src`, `public`, `iwsdk.config.json`) are clean, so the T0.6 cleanup worked. No `src/assets.ts` URL remains.
- Hypothesis (no code changed): these are framework default strings that are only fetched when a Draco-compressed glTF is loaded or when a controller (not hand) profile is requested. Nothing in the current app triggers either, and the console shows no network request to these hosts. But with controllers connected on a real Quest, the profile download would hit jsdelivr, and a future Draco-compressed asset would hit unpkg - both against rule 10 ("no external service at the core of the experience; demo works without backend"). Options for the main context / user: (a) accept and amend S0.1 step 6 to scan only `src public iwsdk.config.json` plus a documented allow-list for these two framework strings; (b) configure/override the Draco path and input-profile base to local copies if M2 needs Draco; (c) ask `contest-reviewer` whether this violates rule 10. I did not decide this.
