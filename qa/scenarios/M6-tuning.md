# S6.1 · Manopole di taratura (`t_<nome>`, file vivo, foveation, maschera del campo visivo)

> **Changelog 2026-11-07**: scenario creato dal piano M6 (D65, D66, D67; T6.A1–T6.A4, T6.A10). Le righe di log sono quelle del "Contratto dei log e dei parametri di M6" di `docs/plans/M6.md`; se l'implementazione ne cambia una, `xr-engineer` aggiorna il piano ("Esiti") e questo file. Il numero 26 della riga `tuning table` è il numero di voci della tabella del piano (20 essenziali + 6 opzionali): se le opzionali non sono state cablate, `count` è minore e va letto da `tuning table`.

**Milestone**: M6 (fase A) · **Tipo**: PC (emulatore IWER via MCP `iwsdk-runtime`) · **Regole di `CLAUDE.md`**: 3 (prestazioni), 4 (ripresa), 5 (feature detection: `foveation`) · Piano: `docs/plans/M6.md`.
Prerequisiti di implementazione: T6.A1–T6.A4 (il passo 7 anche T6.A10). Convenzioni: `qa/scenarios/M5-gate-notes.md` (preparazione standard, calibrazione delle mani `pinch=grip`: la mano per pizzicare `T` va a `T − D_GRIP`, `D_GRIP` = (−0,038; −0,003; +0,037)).
**Cosa NON si prova qui**: le manopole di **tempo e di angolo** (`longPress`, `palmOpenHold`, `palmOpenDeg`, …) non si possono misurare in IWER (latenza MCP di 1–3 s, pose esatte, nessun tremore): per queste valgono i test unitari (il consumatore segue il valore) e la riga di log `tuning set`. Qui si provano solo gli effetti **geometrici e deterministici**.

## Convenzioni
- Preparazione standard di M5 per ogni passo: scrivere `dev-params.local.txt` (una riga), `browser_reload_page`, `xr_accept_session`, `xr_set_input_mode {mode: "hand"}`, attesa 3 s, testa a (0; 1,6; 0), mani a riposo (∓0,30; 1,10; 0,10).
- `BASE` = `house=apartment-a&role=visitor&reset=1&seed=1&debug=1&pinch=grip&time=2026-12-21T10:00`.
- Il file vivo è `tuning.local.txt` nella **radice del progetto** (una riga, stesso formato; ignorato da git).
- Il menu `pinned` si apre con un pizzico sul pulsante `ui:menu-button-right` (`ecs_query_entity` con `["Transform"]`, mano destra a `T − D_GRIP`, `xr_select {duration: 0.3}`); si chiude con lo stesso pulsante. La distanza è nella riga `menu view maxAngleDeg=… distance=…`.

## Passi
1. **Riferimento (default)**. `dev-params.local.txt` = `BASE`. Letture: log `pattern: "tuning|params|miniature placed"` → riga `tuning table count=<n> debug=true`, nessuna riga `tuning set`, riga `params …` senza `hud=0` né altro in coda rispetto a M5; `miniature placed` → `O0` (atteso x=0, y=1,350, z=−0,450). Aprire il menu `pinned`: `menu view … distance=D0` (atteso ≈ 0,59). Chiudere. Marcatore: `ecs_query_entity` `viewpoint:V2` con `["Transform"]` → `M2`; mano destra a `M2 + (0,032; 0; 0) − D_GRIP`, `xr_select {duration: 0.3}`, attesa 2,5 s: log `pattern: "viewpoint"` → **nessuna** riga `viewpoint transition start id=V2` (raggio 0,025 < 0,032). Se il pizzico seleziona una stanza o avvia un trascinamento, annotarlo (non è un FAIL).
2. **Manopole da file**. `dev-params.local.txt` = `BASE&t_pinnedDistance=0.65&t_anchorForward=0.55&t_anchorDown=0.30&t_viewpointRadius=0.045`, ricaricare. Log `pattern: "tuning|miniature placed"` → quattro righe `tuning set <nome>=<valore> default=<d> source=file`. `miniature placed` → y=1,300 e z=−0,550 (testa a 1,6; 0). Aprire il menu `pinned`: `distance` ≈ 0,68 (√(0,65² + 0,20²) = 0,680 ± 0,01), `maxAngleDeg` letto e annotato (può superare 30°: **non è un FAIL**, è la conseguenza dichiarata del valore). Pizzico a `M2 + (0,032; 0; 0)` come al passo 1 (il marcatore è ora in un'altra posizione: rileggere `M2` con `ecs_query_entity`): log `viewpoint transition start id=V2 from=tabletop` **presente**. Tornare al plastico (`ui:tabletop-button` o ricaricare).
3. **Limiti, nomi sbagliati, vincoli**. `dev-params.local.txt` = `BASE&t_pinnedDistance=3&t_bogus=1&t_longPress=abc&t_palmOpenDeg=50&t_palmCloseDeg=45`, ricaricare. Log: `tuning clamped name=pinnedDistance requested=3 applied=0.75` (warn), `tuning ignored name=bogus reason=unknown` (warn), `tuning ignored name=longPress reason=not-a-number` (warn), `tuning set palmOpenDeg=50 …`, `tuning ignored name=palmCloseDeg reason=order` (warn; l'ordine di elaborazione è quello della tabella; se l'ingegnere ne ha scelto un altro, vale quello scritto in "Esiti" di `docs/plans/M6.md`). Nessuna eccezione, nessun `error`. Aprire il menu `pinned`: `distance` ≈ 0,80 (√(0,75² + 0,20²) = 0,776 ± 0,01).
4. **Senza `debug=1` le manopole non valgono**. `dev-params.local.txt` = `house=apartment-a&role=visitor&reset=1&seed=1&pinch=grip&t_pinnedDistance=0.65&t_longPress=1.2` (nessun `debug`). Log: almeno una riga `tuning ignored name=… reason=needs-debug` (warn) per ogni nome, **nessuna** `tuning set`, nessuna `tuning table`; aprire il menu `pinned`: `distance` = D0 (default; la riga `menu view` esiste anche senza `debug`). Nessuna riga `[soglia:stats]`.
5. **Canale vivo (senza ricaricare)**. `dev-params.local.txt` = `BASE`, ricaricare, sessione XR attiva. Aprire il menu `pinned`: `distance` = D0, chiudere. Scrivere `tuning.local.txt` con `t_pinnedDistance=0.62`; attendere 3 s (il sondaggio è ogni 2 s): log `tuning set pinnedDistance=0.62 default=0.55 source=live`; `xr_get_session_status` → `sessionActive: true` (**nessuna ricarica**). Riaprire il menu: `distance` ≈ 0,65 (√(0,62² + 0,20²) = 0,651 ± 0,01). Scrivere un file con due righe valide e una non valida (`t_pinRadius=0.03&t_pickMargin=0.02&t_zzz=1`): le valide si applicano (`source=live`), la non valida dà `tuning ignored name=zzz reason=unknown`. **Cancellare il file**; attendere 3 s: log `tuning cleared`; riaprire il menu: `distance` = D0 (i valori del file tornano ai default dell'URL). Nessun `fetch` verso `tuning.local.txt` nei log di rete se la pagina è la build di produzione (verificato con `quest-scripts`/build: vedi S6.4 passo 11, non qui).
6. **Foveation**. `BASE&t_foveation=0.5`: log `tuning foveation applied=0.5` **oppure** `tuning foveation skipped reason=no-api` (entrambi PASS: in IWER dipende dal renderer); nessun `error`. Con `t_foveation=7` → `tuning clamped name=foveation requested=7 applied=1`.
7. **Maschera del campo visivo** (solo se T6.A10 è consegnato; altrimenti ➖). `BASE&t_fovMask=30`, sessione XR: log `fov-mask on halfAngleDeg=30`; `ecs_find_entities` `^debug:fov-mask$` → 1; `browser_screenshot` → allegare (anello nero ai bordi, centro libero); `[soglia:stats]` `callsPerView` = quello del passo 1 + 1 (±1). Con `t_fovMask=0` o senza il parametro: 0 entità. Cambio dal file vivo `t_fovMask=45`: la maschera si aggiorna (`fov-mask on halfAngleDeg=45`) senza ricaricare; cancellando il file: `fov-mask off`.
8. **Default invariati**. Ricaricare con `BASE` senza `t_*` e rifare i passi 1 (distanza D0) e il pizzico del marcatore a 0,032: gli esiti sono quelli del passo 1.
9. Log senza filtro (`error`, `uncaught`, `Cannot read`, `reading 'add'`, `Missing glyph`, `budget exceeded`): nessuna riga oltre ai `warn` voluti dei passi 3, 4 e 5; pulizia (`dev-params.local.txt` e `tuning.local.txt` rimossi).

## Verifiche (tutte obbligatorie)
1. **Passo 1**: `tuning table count=<n>` presente; nessuna `tuning set`; `params` come in M5; `O0` = (0; 1,35; −0,45); `D0` ≈ 0,59; nessuna transizione del punto di vista a 0,032 m dal marcatore.
2. **Passo 2**: ogni manopola impostata ha la sua `tuning set … source=file` con il default giusto (0,55 / 0,45 / 0,25 / 0,025); posizione del plastico y=1,300, z=−0,550; `distance` ≈ 0,68; il pizzico a 0,032 m **avvia** `viewpoint transition start id=V2`.
3. **Passo 3**: le quattro righe (`clamped`, `ignored unknown`, `ignored not-a-number`, `ignored order`) e `tuning set palmOpenDeg=50`; `distance` ≈ 0,78 (limite 0,75); nessun `error`.
4. **Passo 4**: senza `debug=1` nessuna manopola vale (`needs-debug`), nessuna riga `[soglia:stats]` né `tuning table`, `distance` = D0.
5. **Passo 5**: il cambio dal file arriva entro 3 s, senza ricaricare (la sessione resta attiva), `distance` ≈ 0,65; una riga non valida non ferma le valide; `tuning cleared` alla cancellazione e ritorno a D0.
6. **Passo 6**: una delle due righe di `foveation`; clamp a 1; nessun `error`.
7. **Passo 7** (T6.A10): entità `debug:fov-mask` solo con `fovMask` > 0; +1 chiamata (±1); screenshot allegato; ➖ se il task è tagliato.
8. **Passo 8**: con i default il comportamento coincide con il passo 1.
9. Console: 0 `error`; 0 `warn` oltre a quelli attesi (passi 3–5); nessun `Missing glyph`, nessun `reading 'add'`.
10. **Solo visore** (alta): le manopole di tempo e di angolo (protocolli di `docs/plans/M6.md`); il canale vivo arriva al visore dal server di sviluppo; `setFoveation` esiste nel Quest Browser e cambia il tempo di GPU; la maschera come approssimazione del campo visivo stretto.

## Esito
PASS se le verifiche 1–6, 8 e 9 sono soddisfatte (7 se T6.A10 c'è) · FAIL altrimenti.
