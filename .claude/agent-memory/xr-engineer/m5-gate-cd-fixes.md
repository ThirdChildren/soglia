## F-D-2: Rotate button vs menu targets
- Real geometry: pinned-menu `ui:menu-undo` (-0.1405, 1.431, -0.55) sits INSIDE the Rotate rectangle of a piece at plan (2,2) (button centre (-0.174, 1.4334, -0.5306), 11 x 5 cm, depth tolerance 5 cm). Rotate registers first, so while shown it swallowed Undo presses; the QA's undo came when the 12 s window had already ended (hidden button, stale `epos`). Either way the two cannot coexist.
- Fix (simplest): `rotateDecision` got `covered` (required input); `visible = !covered`, the window keeps running (not ended). `rotateCoveredBy({menu, issues, view})` names the surface (menu first). System reads `isPalmMenuOpen()`, `isIssuePanelOpen()`, `isViewPanelOpen()` every frame AND in `onPinch` (the menu can open with the very pinch that Rotate sees first). Log `rotate button covered by=menu|issues|view` once per change (only if the button was shown); the next `rotate button shown` says it is back. Both menu modes hide it (palm menu too: simpler than computing slot distances).
- Consequence for the flow: with the pinned menu open (stays open after placing) Rotate is not available; close the menu (Menu button) within 12 s. Noted in DEBT.
- Verified IWER (cloud, grip): menu open + piece placed -> no `shown`; pinch at the old button spot -> only `undo action=place`; close menu -> `shown`; open -> `covered by=menu`; close -> `shown`; View and Issues panels -> `covered by=view|issues`. Scripts `fd2*.sh` in the scratchpad (drop takes WORLD x z: use `w 2 2`).
- Not covered (not asked): fixed side buttons (Menu/Issues/View/Tabletop at x +-0.43, y 1.635); Rotate stays in the 30 deg cone at <= 0.65 m so its edge can come within ~2 cm only at the cone extreme with the model panned far to the side.

## F-D-1: `Missing glyph info for character "x"` (UIKit font race)
- Cause (read in `node_modules/@pmndrs/uikit/dist/text/font.js`): `computedFont` is an effect per Text; `result` keeps the LAST font until the newly requested one arrives. A panel is built with UIKit's bundled ASCII Inter; `applyPanelFont` sets our `fontFamilies` later (in `update`, once the doc exists). If our atlas is not in UIKit's `fontCache` yet, UIKit fetches it (async) and the text written right after is laid out with the bundled font -> `getGlyphInfo` warns per missing char. The `normal` atlas (`inter-regular`) is first requested by UIKit at the FIRST MENU OPEN (nothing earlier uses weight normal), 0.5 s before the warn - exactly the QA timing. `loadPanelFonts` only `fetch`ed the files; it never fed UIKit's cache.
- Deterministic repro (temp hacks, removed): delay the 2nd+ fetch of `inter-regular.json` by 2.5 s in `window.fetch` AND delay `applyPanelLook` in palm-menu `update` by 1.5 s after the title element exists (so the bundled font has arrived). Result before fix: 2 warns `Missing glyph ... "x"`; after fix: 0.
- Fix: `src/logic/font-preload.ts` (`preloadFonts(urls, load, timeout)`, pure, 5 s limit, never rejects, threw loader = missing) + `warmUiKitFont` in `src/ui/fonts.ts`: for each atlas url a `new UIKit.Text({text:' ', fontFamilies:{inter:{normal:url}}})` is added to a bare `Object3D` (a Text only enables its properties once it has ANY parent, `isAttached = parent != null`), `probe.fontSignal.subscribe(font => font && onLoad())`, then probes are disposed. `fontFamilies` is assigned only after the preload, and `loadPanelFonts` is awaited before any panel exists. Logs: `font preload ready atlases=2` or warn `font preload incomplete missing=N`.
- TRAP (cost ~20 min): `import { loadCachedFont } from '@pmndrs/uikit/dist/text/cache.js'` works for types and shares the chunk, but as a new optimizer entry it breaks UIKit's module evaluation order: the page dies with `Cannot read properties of undefined (reading 'optional')` (zod schema cycle) and the bridge only shows an `editor` client / "application frame is unavailable". `import '@pmndrs/uikit'` first does NOT help. A stale `node_modules/.vite` keeps the broken graph even after removing the import: stop the server, `rm -rf node_modules/.vite`, start again. A test forbids the deep import.
- Check a page error without the bridge: Playwright script with `--ignore-certificate-errors` against https://localhost:8081/ printing `pageerror` (scratchpad `pwcheck.mjs`, `PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers`).
