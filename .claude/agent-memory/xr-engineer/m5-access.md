Built 2026-11-06 on branch `claude/charming-cori-mccw6h` (plan `docs/plans/M5.md`, D58-D60; T5.16 and the Issues panel at large text NOT done).

- Prefs: `prefs.contrast`, `prefs.largeText`, `prefs.coach` (all saved). `contrast=`/`text=` in URL/dev file win over the saved ones, `0`/`normal` included: `RestoreContext.contrastExplicit/textExplicit` leave the field OUT of `Restorable.prefs` (`RestorePrefs` fields are optional; absent = keep the session value). `coach` absent in an old save is derived in `deserialize`: pieces -> `done`, `menuOpened` -> `grab`, else `menu-button`. Log lines in `src/logic/access.ts` (`access contrast=on source=ui|url|saved`, `access text=large source=... menu=normal issues=normal`, `access applied recolored=N`).
- Theme (`src/ui/theme.ts`): module state `setAccessibility`, getters `getPalette/getUiColors/getFitColors`, `chipLook(active)`, `contrastRatio/luminance`, `themedColor(prop, original)`, `onAccessChange(listener => count)`/`notifyAccessChange`. `src/systems/access.ts` `installAccess(store)` must run BEFORE the house and the panels are built (index.ts) and then follows the store.
- THE hook for every panel: `applyPanelLook(doc, rootId, mode)` in `src/ui/panel-theme.ts` (mode `none|font|layout`). It walks the UIKit tree (`root.traverse`, `node.properties.peek()` gives resolved values, `setProperties` patches), remembers the ORIGINAL colours/fontSize/width/padding per node in a WeakMap (so it is idempotent and reversible), and registers the doc with `onAccessChange` until `doc.disposed`. UIKit in-place recolour WORKS (D58 fallback not needed); an old panel needs no rebuild. `font` = only fontSize x1.25 (2.4 -> 3.0), `layout` = fontSize + root width + paddings x1.25. Colours the code sets itself (chips, tabs) come from `chipLook()`.
- Large text, what each panel does: View panel has its own layout/asset (`view-panel-large.uikitml`, generated from the normal one by a script that reproduces the normal file byte for byte; `ViewLayout` objects + `layout*` functions in `src/logic/view-panel.ts`; panel REBUILT on a text-size change because the switch is in it, log `view panel rebuilt text=large`); 40 x 41 cm, cone 27.8 deg at 0.59 m. Fixed buttons (`menu/issue/view/tabletop`) are `layout` mode and their pick rectangles are widened with `widenButtons`/`widthFactor` (x1.25) - at 3.0 cm "Menu" is 8.3 cm wide, it does NOT fit the 8 cm box. Labels/hints are `font` mode, extents NOT scaled (DEBT). Measure label is `layout` (width 14 would break "140 cm").
- "Contrast" label needs 10.2 cm at 2.4 bold: label cell is 11 cm (value 10.8) now, padding-left 0.4.
- View panel switch rows: `-` sets off, `+` sets on, the value cell (`ui:view-contrast`, `ui:view-text`) flips. 15 anchors + Close.
- Rotate button: `src/logic/rotate-button.ts` (window 12 s on an injected clock, `rotateDecision`), `src/systems/rotate-button.ts`, panel 11 x 5 cm, render order 1003. TRAP: it must register BEFORE everything that takes a pinch (menu, grab, rooms) or the control/piece under it gets the pinch; and because a later `claim(hand,'menu')` by the same owner returns true, the menu/buttons/Issues sites now skip when `ownerOf(hand) === 'menu'` (5 one-line guards). IWER: pinch the button with `pe.sh '^ui:rotate-button$'` (its Transform is world); the window is only 12 s, so grab + press in one script (script `grabchair.sh`/`grabchair2.sh`). Do not leave the menu open and press at the same place before this guard: it triggered `undo`.
- Coach: `src/logic/coach.ts` (steps, 20 s per step timeout on an injected clock, hand animation `menuButtonPose`/`grabPose`), `src/systems/coach.ts`, `src/ui/coach-panel.ts` (width from `textWidth`, `layout` mode). Text of step 1 hangs 7 cm UNDER the right Menu button, pulled inward so its outer edge matches the button's (wide text beside the button covers it); step 2 banner over the menu (eyes + 0.26 m). The hand comes in from the side (fingers 0.94 sideways + 0.35 along the line of sight): seen along the fingers it is a bar. Waits while a piece is held or the Issues/View panel is open. TRAP: an entity's `object3D.name` is set AFTER `addComponent(StableId)`, so a `qualify` subscription cannot read the name: look it up lazily by iterating `queries.named.entities` (cached).
- Measured (IWER, A, role tenant/visitor): K1 48 per view; cold with hint + coach step 1: 57; coach step 2 with menu open: 62; worst case (HC + large, menu dimmed open, sofa held over armchair, FitCheck + reason labels): 65. View panel worst-case overlap: a persistent reason label still covers the lower rows of the View panel (M2 W7).
